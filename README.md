# Резервное копирование Яндекс Диска через браузер

[![Python](https://img.shields.io/badge/Python-3.10%2B-blue)](https://www.python.org/) [![Playwright](https://img.shields.io/badge/Playwright-Chrome-green)](https://playwright.dev/python/) [![GitHub](https://img.shields.io/badge/GitHub-sailoksis-181717?logo=github)](https://github.com/sailoksis)

**Автор:** [sailoksis](https://github.com/sailoksis) · **Репозиторий:** [yandex-disk-browser-backup](https://github.com/sailoksis/yandex-disk-browser-backup)

**Yandex Disk Browser Backup** — бесплатный Python-скрипт для создания локальной копии файлов из Яндекс Диска с помощью **Playwright и Google Chrome**, без обращения к официальному REST API Яндекс Диска.

Проект предназначен для пользователей, которым нужно сохранить содержимое своего облачного хранилища на компьютер, включая вложенные папки, и иметь возможность продолжить работу после прерывания.

> **Важно:** это неофициальный инструмент, не связанный с Яндексом. Его работа зависит от текущего веб-интерфейса Яндекс Диска. Не удаляйте оригиналы из облака, пока не проверите резервную копию.

## Возможности

- Обход папок Яндекс Диска с сохранением вложенной структуры, включая пустые папки.
- Скачивание файлов разных типов: фотографий, видео, документов, архивов и других.
- Сохранение состояния в **SQLite**: можно прервать процесс и продолжить позже.
- Пропуск уже обработанных файлов при обычном запуске.
- Повторные попытки для неудачных загрузок отдельной командой.
- **Резервный режим для изображений:** если оригинал не скачивается, программа пытается открыть фотографию в просмотрщике и сохранить её отображаемую версию как PNG.
- Вычисление **SHA-256** для успешно скачанных файлов и повторная локальная проверка.
- Экспорт каталога файлов и результатов в CSV и JSON.
- Диагностические файлы для анализа ошибок.
- Ручная авторизация, включая CAPTCHA и дополнительные проверки безопасности.

**Ограничение режима предпросмотра:** PNG-скриншот не является оригинальным файлом. У него могут быть другие разрешение, качество и метаданные. Поэтому он сохраняется отдельно с суффиксом `.preview.png` и учитывается в отдельном статусе.

## Требования

- **Windows 10/11** (основной сценарий использования и тестирования).
- **Python 3.10 или новее**.
- **Google Chrome**.
- Доступ к Яндекс Диску через браузер.
- Свободное место на диске под резервную копию.

В текущей версии используется `channel='chrome'`, поэтому установленный браузер Google Chrome необходим. Playwright управляет им автоматически.

## Установка

### 1. Скачайте проект

Скачайте ZIP-архив репозитория через **Code → Download ZIP** на GitHub или клонируйте репозиторий:

```bash
git clone https://github.com/sailoksis/yandex-disk-browser-backup.git
cd yandex-disk-browser-backup
```

Если репозиторий ещё не опубликован, сначала опубликуйте его на GitHub. Если скачали ZIP, просто распакуйте его и откройте терминал в папке проекта.

### 2. Установите зависимости

```bash
py -m pip install -r requirements.txt
```

Если файла `requirements.txt` пока нет, установите Playwright напрямую:

```bash
py -m pip install playwright
```

Если команда `py` недоступна, попробуйте `python`.

> Скрипт использует установленный Google Chrome. Установка отдельного Chromium через `playwright install chromium` для этого режима обычно не требуется.

## Быстрый старт

Команды ниже выполняются из папки проекта.

### Шаг 1. Выберите папку для резервной копии

По умолчанию файлы сохраняются в:

```text
E:\YandexBackup
```

**Если диска E: у вас нет**, обязательно укажите собственный путь через переменную `BACKUP_DIR`.

**PowerShell:**

```powershell
$env:BACKUP_DIR = 'D:\YandexBackup'
```

**Git Bash:**

```bash
export BACKUP_DIR='D:\YandexBackup'
```

**Командная строка Windows (cmd):**

```cmd
set BACKUP_DIR=D:\YandexBackup
```

Переменная действует в текущем окне терминала. При запуске из нового окна её потребуется указать снова.

### Шаг 2. Авторизуйтесь в Яндекс Диске

```bash
py main_sqlite_final.py login
```

Откроется окно Google Chrome. Войдите в свой аккаунт Яндекса, пройдите CAPTCHA или подтверждение входа при необходимости и нажмите **Enter** в терминале.

Профиль браузера сохраняется в папке `.yandex-browser-profile` рядом со скриптом. Повторная авторизация обычно не требуется, пока сессия действительна.

### Шаг 3. Просканируйте Диск

```bash
py main_sqlite_final.py scan
```

Скрипт обойдёт папки и сформирует каталог в SQLite. Сканирование может занять время — особенно при большом количестве вложенных папок.

Для пробного обхода ограниченного числа папок:

```bash
py main_sqlite_final.py scan --max-folders 10
```

Для продолжения сканирования запустите `scan` снова. Перед началом скачивания полный обход должен завершиться (`scan_complete: true`).

### Шаг 4. Проверьте состояние

```bash
py main_sqlite_final.py status
```

### Шаг 5. Скачайте файлы

Для проверки на небольшой партии:

```bash
py main_sqlite_final.py backup --limit 20
```

Для продолжения и скачивания всех ещё не обработанных файлов:

```bash
py main_sqlite_final.py backup
```

Обычный `backup` обрабатывает только файлы со статусами `missing` и `pending`. Уже скачанные оригиналы, сохранённые скриншоты и известные ошибки не повторяются при каждом запуске.

### Шаг 6. Проверьте результат

```bash
py main_sqlite_final.py verify
py main_sqlite_final.py status
```

Команда `verify` проверяет локальные файлы и сопоставляет SHA-256 с ранее записанным значением, если оно имеется. Она **не сравнивает** файлы с независимым хешем оригинала на серверах Яндекса.

## Все команды

| Команда | Назначение |
|---|---|
| `login` | Открыть браузер и войти в аккаунт |
| `scan` | Просканировать папки и сформировать каталог |
| `scan --max-folders 10` | Пробный ограниченный обход |
| `scan --retry-scan-errors` | Повторно проверить папки с ошибками сканирования |
| `backup` | Скачать новые и ещё не обработанные файлы |
| `backup --limit 20` | Обработать не более 20 файлов |
| `retry-failed` | Повторить загрузку файлов со статусом `failed` |
| `retry-failed --limit 20` | Повторить не более 20 проблемных файлов |
| `retry-preview` | Попробовать получить оригиналы вместо сохранённых скриншотов |
| `retry-preview --limit 20` | Повторить не более 20 файлов со статусом `preview` |
| `verify` | Проверить локальные файлы и их SHA-256 |
| `status` | Показать статистику |
| `export` | Обновить CSV- и JSON-отчёты |
| `confirm-empty --path "путь/папки"` | Вручную подтвердить, что папка с ошибкой действительно пуста |

Команда `confirm-empty` предназначена только для случая, когда вы **лично проверили** соответствующую папку в браузере. Она требует дополнительного подтверждения `EMPTY`.

## Как понимать статусы файлов

| Статус | Значение |
|---|---|
| `done` | Оригинал скачан и учтён в базе |
| `existing` | Локальный файл обнаружен и учтён при проверке |
| `preview` | Оригинал недоступен, но сохранён PNG-скриншот из просмотрщика |
| `failed` | Не удалось скачать оригинал или сохранить доступное изображение |
| `missing` | Файл ещё не сохранён локально |
| `pending` | Файл ожидает обработки |
| `mismatch` | При проверке SHA-256 обнаружено несовпадение |

**Не считайте `preview` полноценным успешным скачиванием оригинала.** Для таких файлов желательно позже запустить `retry-preview`.

## Если скачивание не работает

Яндекс Диск может не запускать загрузку, отменять её или показывать пустой/чёрный экран в просмотрщике.

В этом случае программа:

1. Пытается скачать оригинал обычной кнопкой в браузере.
2. Если загрузка не начинается в заданное время, для поддерживаемых изображений открывает просмотрщик.
3. Если изображение загрузилось, сохраняет отображаемую версию как `имя_файла.jpg.preview.png`.
4. Если изображение недоступно или файл другого типа, отмечает его как `failed`.
5. Переходит к следующему файлу, не останавливая весь процесс.

Если позже доступ восстановится, повторите попытки:

```bash
py main_sqlite_final.py retry-failed
py main_sqlite_final.py retry-preview
```

**Для видео, документов и архивов скриншот не создаётся.** Программа не восстанавливает повреждённые или недоступные оригиналы из ничего.

## Настройки

Параметры задаются переменными окружения **перед запуском**.

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `BACKUP_DIR` | `E:\YandexBackup` | Папка резервной копии и базы SQLite |
| `BROWSER_PROFILE` | `.yandex-browser-profile` | Путь к профилю Chrome |
| `DOWNLOAD_START_TIMEOUT_MS` | `5000` | Ожидание начала загрузки, миллисекунды |
| `DOWNLOAD_COMPLETE_TIMEOUT_SECONDS` | `1800` | Максимальное ожидание завершения скачивания, секунды |
| `DOWNLOAD_DELAY_SECONDS` | `0.2` | Пауза после успешного скачивания, секунды |

Например, в PowerShell можно увеличить ожидание начала загрузки до 10 секунд:

```powershell
$env:DOWNLOAD_START_TIMEOUT_MS = '10000'
py main_sqlite_final.py backup
```

Это влияет на ожидание **начала**, а не на время передачи всего файла. Слишком маленькое значение может увеличить число случаев, когда вместо доступного оригинала сохраняется только скриншот.

## Какие файлы создаются локально

Внутри `BACKUP_DIR` появятся:

```text
YandexBackup/
├── 2016/
│   ├── photo.jpg
│   └── another.jpg.preview.png
├── _backup.sqlite3
├── _backup_inventory.csv
├── _backup_summary.json
├── _download_diagnostics/
└── _scan_diagnostics/
```

- `_backup.sqlite3` — каталог и состояния задач; не удаляйте его во время работы.
- `_backup_inventory.csv` — перечень файлов и их статусов.
- `_backup_summary.json` — сводная статистика.
- `*_diagnostics/` — сведения и снимки экрана для диагностики.

Фактический набор файлов зависит от выполненных операций и ошибок.

## Продолжение после прерывания

Если нужно остановить работу, нажмите **Ctrl+C** в терминале. Завершённые операции сохраняются в SQLite.

Позже повторно выполните:

```bash
py main_sqlite_final.py backup
```

Для работы с той же резервной копией важно сохранить **тот же `BACKUP_DIR`**. Не запускайте одновременно два экземпляра скрипта с одной базой SQLite и одним браузерным профилем.

## Известные ограничения

- Проект работает через веб-интерфейс Яндекс Диска, поэтому изменения HTML и кнопок могут потребовать обновления скрипта.
- CAPTCHA и подтверждения входа выполняются пользователем вручную.
- Скорость зависит от браузера, соединения, числа файлов и доступности сервиса.
- Сканирование касается доступного скрипту раздела «Файлы»; некоторые системные разделы могут не входить в обход.
- Наличие `scan_complete: true` означает завершение предусмотренного скриптом обхода, но не гарантирует, что веб-интерфейс показал абсолютно все облачные объекты.
- Скриншот из просмотрщика может иметь меньшую детализацию, чем исходная фотография.
- Проверка SHA-256 подтверждает соответствие локального файла записанному локальному хешу, а не совпадение с облачным оригиналом.
- Файлы со статусом `mismatch` требуют отдельного внимания: обычная команда `backup` их автоматически не повторяет.
- Программа не обходит CAPTCHA, ограничения доступа или защиту аккаунта.
